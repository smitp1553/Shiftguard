## How to read this

- Escalation checks counted: CKV_AWS_286 (policy allows privilege escalation), CKV_AWS_289 (permissions management without constraints), CKV_AWS_61 (role can be assumed by any principal).
- A "yes" only means one of those checks failed on a resource whose name matches the principal or its target. It does not mean Checkov understood the whole path.
- The matching is by resource name, so it is a rough guess (TODO: match by real resource address).
- Checkov has hundreds of checks for other things (encryption, logging, networking). ShiftGuard only does IAM escalation, so this is not a fair fight on coverage, only on this one question.
